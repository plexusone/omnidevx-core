    omnidevx-core v0.4.0 Release Notes¶

    Release Date: 2026-10-07

    Overview¶

    Fourth release of omnidevx-core: the foundation for finding, understanding, and resuming coding-agent sessions. It adds a session catalog alongside the existing event pipeline, a Claude Code session reader, and the building blocks that link a session to the repositories and work items it touched.

    Events are unchanged and remain metadata only. The session catalog is a separate read path that exists so a person can recognize a session by its title and typed prompts; its data is held in memory, never written to the event store, and never turned into an Event. See the Privacy Model.

    Highlights¶

    • Session catalog — The new sessions package defines Session, Reader, Catalog, and ResumeSpec. A catalog merges readers newest-first, resolves session IDs by unique prefix (an ambiguous prefix lists at most eight candidates), and keeps one failing reader from hiding the others. Readers report what to run to resume a session and leave running it to the caller.

    • Claude Code session reader — Lists sessions using bounded reads of a transcript's start and end rather than a full parse. It tells typed prompts from tool results and injected context, and reports whether a session is running from live-process records verified against the process's start time.

    • Evidence model — A data model for the repositories, files, commits, and work-tracking IDs a session touched, documented as a lower bound.

    • Repository index — Maps any path to its git repository by deepest match, deriving a stable ID from the origin remote. Linked worktrees and submodules are supported.

    • Work references — Extraction of work-tracking identifiers using named, validated regular-expression rules. The defaults match INIT- and RMI- IDs, and rules are configurable.

    • Configuration — Optional settings load from ~/.plexusone/omnidevx/config.json: workspace roots and work-reference rules. A missing file gives defaults, and unknown keys are rejected.

    • Published schema — A JSON Schema for sessions.Session is generated from the Go structs and embedded in sessions/schema. Tests fail when the schema and the structs disagree.

    Current Limits¶

    • The session readers do not populate Evidence yet. The model, the repository index, and work-reference extraction are in place; filling evidence from transcripts arrives in a later release.
    • On Windows the Claude Code reader cannot verify that a session is running, so it never reports one as running. Sessions are listed and resumable; check for an open Claude Code window before resuming. This was fixed in v0.4.1; the start time can in fact be read on Windows.
    • Only the Claude Code reader ships in this module. The Codex CLI reader lives in omni-openai.

    Installation¶

    go get github.com/plexusone/omnidevx-core@v0.4.0

    Usage¶

    reader, err := claudecode.NewSessionReader(claudecode.Options{})
if err != nil {
    return err
}
cat := sessions.NewCatalog(reader)

list, diagnostics, err := cat.List(ctx, sessions.ListOptions{})
if err != nil {
    return err
}
_ = diagnostics // parse problems, reported rather than fatal
for _, s := range list {
    fmt.Println(s.ID, s.Title)
}
